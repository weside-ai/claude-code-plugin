Several humans, one crew

Two or more people run one crew, each on their own machine with their own companions. They share one crew file, the repo and the ticketing system. Each state of a story has its owners, a question to a person on another machine is a ticket comment, and each machine keeps its own board.

1 · Two machines, one project

Alice runs the coordinator, architecture, acceptance and the epic masters. Bob runs the product role. Nothing runs between the machines: they meet in the repo and on the ticket. Chat between them only wakes someone.

A session knows whose machine it runs on from WE_HUMAN, else from git config user.email. Because each human may name a companion differently, a ticket comment names a session as <role>@<human> (product@bob), never by a companion's name.

2 · One crew file

The crew file in the repo names the humans under humans. Every machine reads the same file; /we:setup asks once whether several people work in the repo and writes the block.

3 · Who moves what

A story leaves a state only by one of that state's owners. Every move reads the status from the ticket first, since each machine keeps its own log and the ticket is the one state both see.

ON_HOLDBob
BacklogBob
SelectedAlice
In ProgressAlice
In ReviewAlice
In TestAlice; only where the crew maps the status
DoneAlice
  • Into Selected only the product role moves a story, with board.py select: the plan is on the default branch, the Ready gate and the lens panel are green, and the session's human runs product. The move writes selected by product@bob, plan <blob>, panel ready-SHOP-12 on the ticket, and that is the coordinator's start signal.
  • Running work (In Progress and later) belongs to its owner. When Bob tries to move such a story, the move is refused and names the question to ask instead: board.py ask --to alice.
  • A status no state maps (a "Blocked" in the ticketing system) has no known owner; the move is refused rather than decided on one machine's guess.
  • In Test exists only where board.states.in_test names the status. With an owner of In Test, Done comes only from In Test.
  • A state nobody owns anyone moves. /we:setup proposes an owner for every state.

6 · The board on each machine

Each machine has its own /board. One session per machine carries its answers: the coordinator where its human runs it, else that human's first role (on Bob's machine, Penny). What the other human decides arrives through the ticket, not through the pane.

  • Signals: each owned status change becomes one to-do for the role that picks it up, once per ticket, state and change.
  • Questions sent to another human wait on that human's label. Withdraw takes the question back: the label comes off and the ticket gets Q7 withdrawn. board.py supersede Q7 --by Q9 replaces it with a sharper one.
  • Replies land as answers with via: ticket and reach the asking session like a button press. A label taken off without a reply reads as Update: is the question still current?
  • Claims live board.claim_hours (default 4) on the ticket; a second claim by another role, human or session is refused while one lives.

8 · Set it up

  1. In the repo, /we:setup. To "Do several people work in this repo, each on their own machine?" answer yes; correct the proposed humans block once. Setup validates the file until crew.py validate --strict prints ok.
  2. On each machine, git config user.email equals that human's email, or export WE_HUMAN=<slug>.
  3. Each human runs wclaude --start inside tmux: the coordinator if they run it, else their first role, the product owner in its own window if they run it, and /we:start offers the rest. wclaude --start --role <key> starts one more.

Setup details: we/skills/setup/references/humans.md · the crew in general: docs/workflow.md.

9 · Next: talking in a weside room

TodayWith a weside.ai account, a companion session writes from Claude Code into a weside room its companion is a member of (send_to_other_room), and the people in that room get the line in the weside app. The other way, the companion's weside side can hand work over to its Claude Code session; the session wakes within a minute and confirms with its human in the terminal before it acts on anything.

In designHumans and companions on different machines talk directly in a shared weside room: a question to Bob reaches Bob's phone, Bob's answer reaches the asking session, and the room's messages show up as an inbox on each board. This is not built and its shape is not decided. Until it is, the ticket stays the bus between machines, as described above.
