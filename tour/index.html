we — Agentic Product Ownership for Claude Code

A Claude Code plugin that turns an outcome into merged, accepted pull requests. A crew of sessions plans the work as epics and stories, workers build one PR per story, and a merge gate lets each PR merge by its computed risk class. You decide what only a person can decide, from one inbox.

1 · Who runs

You, the humanvision, money and prod, and whatever else you choose; one inbox: the board
Companions (owners)product, architecture, acceptance, machinery, coordinator, escalation, HR; each guards one cornerstone and advises. They judge, they do not build
A master per epic/we:master: pulls the epic's stories, starts workers, opens and merges the PRs, cleans up; no product decision
Workersone chunk each in its own worktree (we-worker), report once and end. A subagent reads and reviews, never builds

Who holds which role lives in .weside/crew.json; /we:setup writes it. Every session then starts with the crew process and its role card.

2 · What is built

Goal file→Epic + scope fence→Story = one PR→Plan first
  • Goal file: goals with metrics, no epics. An epic says which metric it serves.
  • Epic (/we:epic): one outcome, a user, a metric, exit criteria and a scope fence. You approve the epic; a story inside its fence needs no further approval.
  • Story: one PR per repo, acceptance criteria as Given/When/Then, each with an oracle class. Its plan docs/plans/PROJ-12-story.md lands on the default branch before code; a refiner worker writes it (/we:plan-story).

4 · Who waits on whom: the risk class

A classifier over .weside/risk-paths computes each PR's class. The merge gate (a hook on every merge and auto-merge arm) refuses what breaks the table, refuses any merge from a worker, and holds everything during a freeze.

5 · Your one inbox: the board

A session that needs you sends one question line with its recommendation to the coordinator, who puts it on the board with board.py ask; a cold reader first checks that it stands on its own. The /board pane shows what waits for you, which sessions run and on what. You answer with a button; the coordinator's session carries the answer back to the session that asked, and bundles what is not urgent on the crew's cadence.

6 · Acceptance

  • receipt: a scripted check runs on the first release candidate that carries the story; /we:accept moves green stories to Done.
  • ci: a test in CI, with the reason staging cannot see it.
  • walk: a person or an acceptance worker walks a screen, only where no script sees it.

7 · Watch it: /flow and /board

/flow is a pane with one traffic light per step, for a story, every story of an epic, or this session's work. It reads git and GitHub on its own; buttons run the next verb.

8 · Limits and restarts

  • A session that hits its usage limit resumes with /we:resume (or "weiter"): open items, workers, CI watches.
  • we-worker status shows each worker, its last activity and a usage limit with its resume command; we-worker stop stops one before a replacement starts.
  • Parked work goes to a pushed wip/ branch; after a compaction a session rebuilds its state from the plan, git, the PR and the ticket.

9 · Alone, without a crew

Without .weside/crew.json the same pipeline runs in one session: /we:epic, then /we:master <epic> plans each story, builds it in a worktree subagent, opens one PR per story, works CI and reviews with /we:ci-review and arms auto-merge; /we:merged cleans up. No board and no role cards; questions come to you at the end of the message, with a recommendation.

/we:standupwhere you are and what you must do next
/we:council · /we:grillrole lenses on a question; one question at a time until a plan holds
/we:retro · /we:optimizefrictions become inbox candidates; you decide, the ledger keeps them

The effort rule

  • The default worker is we:dev-medium: Opus at effort medium.
  • we:dev-high for promises across several code paths, money, transactions or idempotency, fragile paths, a second attempt, and plan-writing.
  • Implementation never runs on Sonnet. One implementer per story; parallel only for disjoint files.

Install

/plugin marketplace add weside-ai/claude-code-plugin
/plugin install we@weside-ai
