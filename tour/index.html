we — Agentic Product Ownership for Claude Code

Plan at four altitudes, build with one Lead, watch every story's step in one pane, deliver one PR that auto-merges once CI and review are through.

Plan→Approval→Build→PR→CI→Review→Merge

1 · Plan

/we:visionthe PRD: audience, problem, intended change, non-bets
/we:sagaa theme that serves the vision
/we:epica bounded initiative with named stories
/we:storyone sprint-sized story with a build-ready plan

/we:meet <altitude> decomposes an artifact one altitude down, with a council of role lenses (/we:council) when you want one. /we:grill stress-tests a plan one question at a time. A story plan lands on the default branch; once you approve it (status: approved) it is ready to build.

2 · Build

/we:orchestrate is the Lead. It refines a story without a plan (/we:refine), dispatches one dev worker per approved plan (/we:develop, in its own worktree), checks the report against the acceptance criteria and the DoD, pushes once, opens one PR and runs /we:ci-review when CI concludes, up to three rounds.

3 · Watch: /flow

A pane beside the transcript with one traffic light per step, for a story, every story of an epic, or whatever this session works on. It reads git and GitHub on its own every two minutes; no agent feeds it. Buttons run the verb the state calls for.

/flow without a key takes the session's focus, its branch, or the keys you named. Details: docs/flow.md.

4 · Deliver

Claude arms auto-merge when CI and the Codex review are through; you merge the exceptions (money path, destructive migration, open question). /we:merged removes the worktrees and branches and moves the tickets to Done.

Around the pipeline

/we:standupwhere this branch stands and whether you must act
/we:ac-reviewa branch against its acceptance criteria and the DoD
/we:retro · /we:optimizefrictions become inbox candidates; you decide, the ledger keeps them
/we:resumeafter a usage-limit stop: open items, workers, CI watches
/we:handoffa restart note for the next session
/we:setupper repo: stack, ticketing, rosters, statusline

The effort rule

  • The default worker is we:dev-medium: Opus at effort medium.
  • we:dev-high for promises across several code paths, money, transactions or idempotency, fragile paths, a second attempt, and plan-writing.
  • Implementation never runs on Sonnet. One implementer per story; parallel only for disjoint files.

The measurements: we/AUTHORING.md.
